# MISO Control BTLV v1 registry

This freezes the semantic registry referenced by [the wire specification](CONTROL_BTLV_V1.md). `R` is one mandatory field, `O` is zero or one optional field, and `R*`/`O*` are contiguous repeats with that flag. Absent optional fields are omitted, never encoded as placeholder zeroes.

## Registries

| Commands and echoed response IDs | Events |
| --- | --- |
| `0001` capabilities get; `0002` session snapshot get; `0003` session transaction apply; `0007` transport get; `0008` transport set; `0009` telemetry configure; `000a` counters get; `000b` diagnostics get; `000c` control list get; `000d` control state get; `000e` response get; `0010` spectrum configure; `0011` spectrum capture; `0012` spectrum stream; `0013` session replace | `8001` session committed; `8010` transport state; `8011` observation ended; `8020` meter batch; `8021` counter snapshot; `8030` diagnostic; `8040` response ready |

`0013` (session replace, #1386) is appended after `000e`. `8040` (response ready, #1578) is appended after `8030`; it shares capability flag bit 14 with `000e`: bit 14 means the endpoint serves `000e` and emits `8040`, and a capabilities record that lists one of them without the other, or sets bit 14 without both, is refused at decode. `000f` (observation read, #1586) is allocated. It has capability flag bit 15 (#1586 D6): bit 15 means the endpoint serves `000f` and the `Observe` edit (`0801`), a capabilities record sets it exactly when it lists `000f`, and both ride the session family, so a record that lists `000f` (or sets bit 15) without command `0003` and event `8001` is refused at decode. A host advertises it when its session serves the `Observe` edit: both hosts do, because every plan binds every declared tap (#1590 D5); a host that did not would list neither and refuse the command as `UNAVAILABLE`. `0010` (spectrum configure, #1594), `0011` (spectrum capture) and `0012` (spectrum stream, #1595) are allocated and every host session serves them. They have capability flag bit 16 (#1595 D8): a capabilities record lists the three together or none of them, and sets bit 16 exactly when it lists them; any other record is refused at decode. Both hosts advertise them and set bit 16, and both SDKs read spectrum through these frames alone (#1596); the browser's own spectrum exports stay until #1597 deletes them, and no SDK path calls them. `0013` has no capability flag bit of its own: it rides the session family, so a capabilities record that lists `0013` without command `0003` and event `8001` (and flag bits `3` and `12`) is refused at decode. An endpoint lists it only when it serves session transactions and its host has a document transport (the control plane's hook): the C ABI lists it (`miso_engine_v1_submit_document_command`); the browser does not, and refuses the command as `UNAVAILABLE`, until #1697 gives it a document transport and turns the advertisement on. `0014` (loudness, #2115) is allocated and every host session serves it. It has capability flag bit 17: a capabilities record sets bit 17 exactly when it lists `0014`, and any other record is refused at decode. Both hosts advertise it and set bit 17.

Message IDs `0004` (parameter metadata get) and `0005` (parameter state get) are **retired** by decision 17 (C4, #1551): the decoder refuses them as `UNSUPPORTED_MESSAGE`, no capability registry lists them, and they are never reallocated (`RETIRED_MESSAGE_IDS`; a conformance row pins each). `CONTROL_LIST_GET` and `CONTROL_STATE_GET` replace them.

Message ID `0006` (automation enqueue) is **retired** the same way (#1627): every sample-timed change is a stored automation edit (`0600`-`0603`), so the command, its success response, statuses `15` and `16`, capability flag bit 5 and capability fields `9`, `12`, `19` and `20` are retired. The decoder refuses `0006` as `UNSUPPORTED_MESSAGE` before any state changes (it is in `RETIRED_MESSAGE_IDS` and pinned by a conformance row), no capability registry lists it or sets bit 5 (a set bit 5 is an unknown flag and refused), a status number `15` or `16` is an invalid status, and a capabilities response that carries field `9`, `12`, `19` or `20` is refused in either flag form, never skipped as an unknown optional field. None is ever reallocated or renumbered. The capabilities record has 23 fields.

Event ID `8002` (automation canceled) is **retired** with it (#1628): with no batch to admit there is nothing to cancel, so a revision change or a transport set cancels nothing and a transaction commit reserves only its `SESSION_COMMITTED`. The decoder refuses `8002` as `UNSUPPORTED_MESSAGE` (it is in `RETIRED_MESSAGE_IDS` and pinned by a conformance row), no capabilities record lists it, and the session family is command `0003` with event `8001`. It is never reallocated or renumbered.

The stored transport position is **retired** (#1635): the protocol keeps no playhead that nothing plays, because the engine has one playhead, which the host moves with source seeks (and, later, the session seek). `TRANSPORT_SET` (`0008`) field `2`, the transport snapshot's field `2` and the `TRANSPORT_STATE` event's (`8010`) field `3` are refused at decode in either flag form (an optional one as `MALFORMED_FRAME`, a mandatory one as `UNKNOWN_REQUIRED_FIELD`), never skipped as unknown optional fields, never reallocated and never renumbered; the remaining field IDs keep their numbers. A `TRANSPORT_SET` that carries one changes nothing and queues no event, and its conformance rows are `retired.transport_set_field_2.*`. The transport state (stopped or playing) stays endpoint-local and readable.

The automation queue is **retired** with its last producer and consumer (#1629): nothing enqueues a batch, so the queue, its 32-byte record, its density and frontier admission and its configuration are deleted. Queue kind `2` (a `BACKPRESSURE` payload naming it fails decode) and counters `2` (`AUTOMATION_BACKPRESSURE`), `11` (`LATE_AUTOMATION`), `12` (`CANCELED_AUTOMATION`), `13` (`AUTOMATION_TIME_PAST`) and `14` (`AUTOMATION_ORDER_REJECT`) are retired the same way: a `TELEMETRY_CONFIGURE` naming a retired counter is refused as `INVALID_FIELD`, a `COUNTERS_GET` naming one is `NOT_FOUND` (as for any counter the endpoint does not report), and a counters snapshot never carries one. None is ever reallocated or renumbered; the next counter takes a new number. Conformance rows pin each refusal.

Status IDs are: `0` OK, `1` malformed frame, `2` unsupported version, `3` unsupported message, `4` unknown required field, `5` invalid field, `6` limit exceeded, `7` revision conflict, `8` revision exhausted, `9` request ID reuse, `10` replay expired, `11` backpressure, `12` validation failed, `13` not found, `14` unavailable, `17` PCM forbidden, `18` internal; `15` and `16` are retired (#1627) and never reallocated.

`QueueKind` is control command `1`, reliable response `3`, reliable event `4`, telemetry `5`, replay cache `6`, spectrum arm slot `7` (#1944: the record of a `spectrum.busy` refusal; capacity 1, no queue generation, as for the replay cache), track-response capture slot `8` (#1578 D3: the record of a `response.capture.pending` refusal; capacity 1, occupancy 1, no queue generation); `2` is retired (#1629). Diagnostic severity is info `1`, warning `2`, error `3`. Transport state is stopped `1` or playing `2`. Parameter enums are: rack inserts/builtins/console `2`/`4`/`5` (decision 12, #1093: `inserts` kept the retired `dynamic` code and `console` is appended; `1` (SIMD1) and `3` (SIMD2) are retired and refused, never reallocated; `builtins` is the strip's own fixed section, appended by issue #178; the same table is the session edits' rack name and an automation target's rack); channel left/right/both `1..3`; unit dB/Hz/ms/samples/linear/ratio `1..6`. Transaction edit path (`0003` and `0013` response field `2`, #1313, #1559, #1386) is live/model_only/rebuild/monitor/unchanged `1..5`: records on the running plan's live lanes, nothing for render to do, a successor plan prepared and published, writes to the host's monitor overlay only (solo and master: no model change, no revision change, no `SESSION_COMMITTED`), and a `0013` whose document is the committed model (nothing committed: `applied-operations` 0, the revision unchanged, no `SESSION_COMMITTED`, no plan; a `0003` never has it); zero and every unallocated value reject. Meter component is left/right/aggregate `1..3`; meter flags are valid/clipped/held bits `0..2`. A meter table entry's target is output `1`, strip `2` or master `3` (#1690 D3: the strip the core's `master` row names now, with no strip ID), and its metric peak `1` or gain reduction `2` (#1583 D1); the output takes peak only and the master gain reduction only, any other pair `INVALID_FIELD`. All unallocated bits reject.

## Common forms

`Diagnostic` is `1:code UTF8 R`, `2:severity U8 R`, `3:path-segment MESSAGE R*`, `4:detail UTF8 O`, `5:operation-index U32 O`, `6:sample U64 O`, `7:provider-sequence U64 O`. A path segment has tag `1:U8 R` and exactly one variant: field name `2:UTF8 O`, index `3:U64 O`, or stable ID `4:UTF8 O`. Provider diagnostic pages/events require sequence.

`Backpressure` is queue kind `1:U8 R`, capacity `2:U64 R`, pre-attempt occupancy `3:U64 R`, requested slots `4:U16 R`, queue generation `5:U64 O`, retry sample `6:U64 O`, requested bytes `7:U64 O`, available bytes `8:U64 O`. Every non-OK response instead has diagnostics `1:MESSAGE R*`, omitted-diagnostic count `2:U32 R`, and backpressure `3:MESSAGE O` exactly when the status is backpressure.

Snapshot continuations and diagnostic pages use an exact revision after an any-revision first page. Control pages (`000c`, `000d`) are guarded by `structure-epoch`, not by the session revision: a control page request is sent with revision `Any`, and the page reports the revision it was read at. Counter values are `1:id U32 R`, `2:value U64 R`, ascending and non-resetting. Counter IDs run 1 to 22, without `2` and `11` to `14` (retired, #1629); `16` is `LIVE_VALUES_SUPERSEDED`, the writes to adopted plans that a later write to the same live cell replaced before a block read them (#1312); `17` is `TRANSITION_REPREPARE_REFUSALS`, the transition re-preparations that were refused anyway and retried at the next service step (#1351 D6, written by #1360); `18` is `STRIPS_RESTARTED`, the strips that a replacement plan render adopted started at rest, each once per adopted plan, added when the control plane promotes that plan (#1768); `19` is `LIVE_BLOCK_ERRORS`, the blocks render refused after the block took its live snapshot, a defect path that stays 0 in a correct build (#1521); `20` is `SOURCE_UNDERRUN_BLOCKS`, the rendered blocks in which a source played zeros because the host had not delivered PCM it owed or a source had no stream, graph-wide, with held blocks and blocks past the end of a region not counted (#1537); `21` is `SOURCE_FRAMES_DISCARDED`, the accepted source frames render never read because the caller's transaction removed or redeclared the source, added when the control plane reclaims the displaced plan (#1699); `22` is `METER_WINDOWS_LOST`, the closed meter windows that never reached a `METER_BATCH` (the meter delivery's losses and the partial batches its fold discarded, #1583 D5). A control-state record is `{handle:u32, value:f32}`; a meter record is `{handle:u32, component:u16, flags:u16, value:f32, reserved:u32}`. Both fixed arrays are validated schema fields, not opaque bytes.

## The control list (decision 17, C4, #1551)

`CONTROL_LIST_GET` returns pages of rows in strictly ascending handle order: an owner header, then its section headers, then the control rows of each section. `CONTROL_STATE_GET` takes the same request and returns the values of the same rows, without the headers. A handle is nonzero and means a row only inside one `structure_epoch`; the epoch changes when the address sequence, a header row or any control row's descriptor (every field except `value`) changes, live commits included (a live `matrix_mode` switch flips `active`), and never when only a value does (ruling of decision 17, C4 amendment of 2026-10-13).

**Request** (both messages): `1:structure-epoch U64 R` (`0` on the first page), `2:after-handle U32 R`, `3:limit U16 R` (`1..=256`), `4:owner-kind U8 O`, `5:owner-id UTF8 O` (present exactly when the owner kind is not the session; stable ID). `6:headers-only BOOL O` (#2206, an in-place V1 amendment): a non-mandatory field, so a peer that does not know it skips it and serves the full list; present only as `true`, and, unlike `include-window` below (absent is false), a present `false` is `INVALID_FIELD` (root ruling of 2026-10-29); with it, a page holds only the owner and section headers of the window, with the same handles, order, epoch and cursor rules as the full list, `limit` counts header rows, `eof` says no header row of the window follows, and a `CONTROL_STATE_GET` page covers the same header rows and so has no record. A request without it is byte-identical to the request before the field existed, and so is its reply. A request whose epoch is not `0` and not the endpoint's current one is `REVISION_CONFLICT` with the diagnostic `control.list.stale`; the caller starts again from handle `0`. Epoch `0` names no structure to continue in, so a request with epoch `0` and `after-handle` other than `0` is `INVALID_FIELD`.

**Address** (`ControlAddress`): `1:owner-kind U8 R` (session `1`, strip `2`, route `3`, VCA `4`), `2:owner-id UTF8 O` (absent exactly for the session), `3:section U8 R` (inserts `2`, builtins `4`, console `5`, own `6`; the first three are the rack codes above), `4:slot-id UTF8 O` (present exactly for console and inserts), `5:control U32 O`, `6:lane U8 O` (left `1`, right `2`, both `3`; `5` and `6` are present exactly in a control row). An owner header carries the `own` section.

**Entry** (`ControlEntry`): `1:handle U32 R`, `2:row-kind U8 R` (owner header `1`, section header `2`, control `3`), `3:address MESSAGE R`. A header row adds `4:header-kind U8` (owner: track `1`, submix `2`, route `3`, VCA `4`, session `5`, and it must agree with the address's owner kind; section: the section code), `5:name UTF8`, `6:effect UTF8 O` (a console or inserts section header only), and for a route owner header `7:source UTF8`, `8:destination UTF8`, `9:tap U8` (the route tap codes below). A control row adds `10:name`, `11:display-name`, `12:display-unit` (UTF8), `13:unit U8` (dB/Hz/ms/samples/linear/ratio `1..6`), `14:kind U8` (continuous `1`, toggle `2`, enumeration `3`), `15:minimum`, `16:maximum`, `17:disabled-value O`, `18:default` (F32), `19:taper U8` (linear `1`, logarithmic `2`, exponential `3`, decibel `4`, stepped `5`), `20:step F32`, `21:precision U8`, `22:ladder PACKED_F32`, `23:choice MESSAGE O*` (value `1:F32`, label `2:UTF8`), `24:ramp-row U8 O` (the live-ramp rows in declaration order: fader `1`, input trim `2`, send gain `3`, VCA offset `4`, link glide `5`, mute `6`, solo `7`, polarity invert `8`, send mute `9`, send follows-mute `10`, VCA mute `11`, bypass crossfade `12`, pan `13`, matrix `14`, send matrix `15`; absent means a fixed ramp), `25:default-ramp-samples U32`, `26:class U8` (live `1`, rebuild-only `2`, derived `3`), `27:reason U8 O` (new memory `1`, new graph `2`, processing order `3`, latency `4`, glitch `5`, optimisation `6`, correctness `7`, ruled live not built `8`), `28:reason-issue U32 O`, `29:reopen UTF8 O`, `30:scope U8` (model `1`, monitor `2`), `31:automatable BOOL`, `32:family U8` (strip level `1`, strip matrix `2`, strip input `3`, route `4`, effect `5`, setting `6`), `33:active BOOL`, `34:value F32`, `35:automated BOOL` (#1650 D4: a rendered stored automation drives the row's lane; on such a lane of a strip's builtin `fader_db` row, `value` is the lane's stored hand-move offset in dB, which a `SET_CONTROL` of the row writes and the curve renders under; on a strip's builtin `mute` row, #1651 R18-2, `value` stays the lane's static (hand) mute, which render ORs with the curve). Header-only and control-only fields are optional on the wire and required or refused by the row kind: a header with a control field, a control row with a header field, a missing required field or a code outside its table is `INVALID_FIELD`.

A control row's own rules: all numbers are finite and `minimum <= maximum`; choices are present exactly for an enumeration, unique, and hold the default and the value; `reason` and `reopen` are present exactly when the class is rebuild-only, and `reason-issue` exactly with reason `8`; a control is automatable only if it is live, in the model scope and not a setting, and the wire check is that implication only: a live row that a ruling excludes from automation is a valid row with `automatable` false. Two rows are excluded (#1632, decision 17 C3): a send's `follows_mute` ("a routing setting, not a performance value") and a strip's `matrix_mode` ("a mode, not a performance value"); an owner request reopens either. A control is automated only if it is automatable; `automated` is a descriptor field, so an automation edit that changes it advances the structure epoch.

**Pages.** The list page is `1:revision U64`, `2:structure-epoch U64`, `3:last-handle U32` (the last row's handle, or the request's cursor on an empty page), `4:eof BOOL`, `5:ControlEntry MESSAGE R*` (at most 256, ascending). The state page has the same first four fields, then count `5:U16`, stride `6:U16=8` and records `7:BYTES`: `{handle:u32, value:f32}` per control row of the covered handles, ascending; `last-handle` is the cursor for the next request and may follow the last record (a header row is covered and has no record). A record array whose width, count, order or values break these rules is refused. Handles are revision-scoped; a record's state flags no longer exist, because a value is always valid.

## The response preview (decision 17, C13, #1573)

`RESPONSE_GET` (`000e`, capability flag bit 14, with event `8040`) asks for the frequency response of one native effect or of the input filters, for parameters the caller chooses. It is a read: it writes no session, revision, catalog or cell, it is sent with revision `Any`, and its reply is cached for exact replay like every reply.

**Request** (`ResponseRequest`): exactly one target of `1:configuration MESSAGE O`, `2:address MESSAGE O` (a `ControlAddress` with `control` and `lane` absent) and `3:strip-id UTF8 O` (a stable ID); `4:grid U8 R` (linear `1`, logarithmic `2`), `5:points U32 R`, `6:minimum-hz F32 R`, `7:maximum-hz F32 R`, `8:channels U8 R` (left `1`, right `2`, both `3`), `9:sections BOOL R`, `10:override MESSAGE O*`, `11:configuration-id U64 O`, `12:sample-rate-hz U32 O`, `13:quantum-frames U32 O`, `14:maximum-prepared-bytes U64 O`, `15:maximum-state-bytes U64 O`, `16:maximum-scratch-bytes U64 O`, `17:maximum-automation-spans U32 O`, `18:maximum-reply-bytes U32 O`. A configuration is `1:kind U8 R` (effect `1`, input filters `2`), `2:effect UTF8 O`, `3:quality U8 O` (draft `1`, normal `2`, high `3`), `4:link-mode U8 O` (dual mono `1`, maximum `2`, average `3`); fields 2 to 4 are present exactly for kind `1`. An override is `1:control U32 R`, `2:lane U8 R` (left `1`, right `2`, both `3`), `3:value F32 R`. The codec refuses with `INVALID_FIELD`, on encode and on decode: not exactly one target, a code outside its table, a `strip-id` that is not a stable ID, and for a strip target `sections` true or any override. The encoder also refuses an empty effect ID, a NaN or infinite endpoint or override value, and for an effect configuration a bypass override (control `0`) that is not lane `both` with a value of exactly `0` or `1`; the decoder reads these as sent, so the core refuses each with its typed code below (#1623): `response.effect.unknown`, `response.grid`, `response.override.value`, `response.override.lane` and `response.override.bypass`.

**Overrides** follow the lane rule of decision 17. For an effect, control `0` is the effect-wide bypass; any other control is a descriptor parameter ID. For the input filters, control `3` is `hpf_hz` and `4` is `lpf_hz` (the builtin parameter IDs); an absent lane takes the row's default. `both` on a per-lane parameter sets both lanes; `left` or `right` on a shared parameter is refused. A (control, lane) pair given twice, or `both` beside `left` or `right` of the same control, is a duplicate. At most 256 overrides.

**Address target** (#1575). An address names a session effect or a strip's input filters by the address its controls have: the owner is a strip (a track or a submix) and the section its `builtins` (the input filters), a `console` slot or an `inserts` effect; any other owner or section, or a `control` or `lane` present, is `response.address`, and an unknown strip, slot or insert is `NOT_FOUND` `control.address.unknown`. The values are the committed model's, the ones a plan rebuild prepares: the builtins section's four cutoffs (rows `3` and `4` on `left` and `right`), and a console entry's or an insert's parameters resolved as preparation resolves them, with the slot's or the insert's quality and link mode and the entry's bypass. A `cid` effect is `UNAVAILABLE` `effect.third_party.unavailable_at_launch`, and an effect with no response `response.effect.unsupported`. An override names a control row of the addressed section: `0` the bypass, `2147483648` (`0x80000000`) the link-mode row of an insert that has one, any other ID a parameter, and in the builtins section only `3` and `4` (`response.override.control` otherwise). Each is checked as a control write by the one validator before anything is prepared, and its refusal is `INVALID_FIELD` with the validator's code (`control.address.unknown`, `control.lane`, `control.domain`, `control.read_only`, `control.inactive`); `both` on a per-lane row sets both lanes, and a duplicate is `response.override.duplicate`. The overrides replace the committed values they name and change nothing in the session. The reply carries the committed revision. Nothing is kept between requests. The session-less entry (#1574) has no session, so it refuses an address as `response.target.unavailable`.

**Result** (`ResponseResult`), all fields optional on the wire and shaped as one of two forms. The tag form is `1:request-tag U64 O` alone (the strip target, whose result arrives later as one `8040` event that carries the tag; [`CONTROL_PROTOCOL_SEMANTICS.md`](CONTROL_PROTOCOL_SEMANTICS.md), "The track response"). The curve form is `2:sample-rate-hz U32`, `3:configuration-id U64`, `4:floor-db F32`, `5:bypass BOOL`, `6:section-count U32`, `7:enabled-left U32`, `8:enabled-right U32`, `9:retained-bytes U64`, `10:frequencies-hz PACKED_F32`, with at least one of `11:left-db PACKED_F32` and `12:right-db PACKED_F32`, and `13:sections-left-db`, `14:sections-right-db` (`PACKED_F32`, section-major) each present only with its side's total. Fields 11 and 12 have the length of field 10 (at least 2 points); fields 13 and 14 have `section-count` times that length. The enabled masks hold bit `min(index, 31)` per enabled section. All values are finite. The codec refuses every other shape, on encode and on decode. `protocol::response_result_encoded_len(points, channels, section_count, sections)` is the exact frame length of a curve reply.

**Refusals** carry one error diagnostic whose `code` is the table below. Overrides, owner and axis codes come from one table in `host_core` (`ResponseQueryError::refusal`). A request that is wrong in several ways is refused with the core's refusal first, in the core's order: rate, points, override count, axis, override values, then the owner's.

| `LIMIT_EXCEEDED` | `response.override.count` | more than 256 overrides |
| `LIMIT_EXCEEDED` | `response.limit` | the owner cannot be prepared within the byte, state, scratch or span bounds |
| `LIMIT_EXCEEDED` | `response.reply_too_large` | the reply frame would exceed the smaller of the endpoint's frame limit, the replay cache's response bound and `maximum-reply-bytes`; refused before any curve is computed |
| `NOT_FOUND` | `response.effect.unknown` | no such native effect, an empty effect ID included |
| `UNAVAILABLE` | `response.effect.unsupported` | the effect has no response |
| `INVALID_FIELD` | `response.address` | an address whose owner is no strip, whose section is `own`, or that carries a `control` or `lane` (#1575) |
| `INVALID_FIELD` | the control code | an address override the control validator refuses: `control.address.unknown`, `control.lane`, `control.domain`, `control.read_only`, `control.inactive` (#1575) |
| `NOT_FOUND` | `control.address.unknown` | an address naming a strip, console slot or insert the session does not have (#1575) |
| `UNAVAILABLE` | `effect.third_party.unavailable_at_launch` | an address naming a `cid` effect (#1575) |
| `UNAVAILABLE` | `response.target.unavailable` | a strip target or an address on the session-less entry |
| `BACKPRESSURE` | `response.capture.pending` | a strip target while the session's one capture is in flight or its `8040` event is unread (#1578 D3); the record is the capture slot (queue kind `8`). The protocol controller refuses it before the provider while its `8040` cell is held. |
| `VALIDATION_FAILED` | the owner's code | the owner refused the configuration, or an address's committed values do not resolve |
| `INTERNAL` | `response.numerical`, `response.internal` | the query failed after it was admitted |

`OBSERVATION_READ` (`000f`, #1586; decision 17, C1 and C13) reads the latest window of up to 256 observation taps by stable address. The read consumes nothing and arms nothing: it never acknowledges a window, so the meter fold still folds it, and a tap is armed only by an `Observe` edit. It is executed by the session (sent with revision `Any`) and cached for exact replay like `0010`.

**Request** (`ObservationReadRequest`): `1:selection MESSAGE R*`, 1 to 256. A selection (`ObservationSelection`) is `1:address MESSAGE R` (the `Observe` edit's address: a `ControlAddress` with owner kind strip and its ID, section console `5` or inserts `2` with its slot ID, and no `control` or `lane`), `2:tap-id U32 R` (the effect-local tap ID), `3:channels U8 R` (left `1`, right `2`, both `3`). An empty request, more than 256 selections, a code outside its table and any other address shape are `INVALID_FIELD` on encode and on decode.

**Reply** (`ObservationReadPage`): `1:observed-sample U64 R` (the render sample at the read: the end of the last rendered block), `2:row MESSAGE R*`, one per selection in selection order. A row (`ObservationRow`) is `1:status U8 R` (pending `1`, unarmed `2`, ready `3`), `2:armed BOOL R`, `3:arm-sample U64 R` and `4:arm-tag U64 R` (the slot's published arm state: the arm or disarm render applied last, or `false`, `0` and `0` when render has not applied the tap's last record), `5:first-sample`, `6:end-sample`, `7:sequence U64 O` and `8:blocks U32 O` (all four present exactly when ready), `9:left` and `10:right F32 O` (each present exactly when ready and asked for), `11:unit U8 R` (the tap's native unit, the unit codes above). A ready row is armed, has a nonzero tag, a window that opened at or after its arm sample and is not empty, and at least one lane. A row that breaks a rule is `INVALID_FIELD` on encode and on decode. Status and refusals are in [`CONTROL_PROTOCOL_SEMANTICS.md`](CONTROL_PROTOCOL_SEMANTICS.md) ("Observation subscriptions").

`SPECTRUM_CONFIGURE` (`0010`, #1594; decision 17, C9 and C13) sets, changes or removes the spectrum taps of a running session. The taps are monitor state: the command changes no model value, no revision and no saved state, emits no `SESSION_COMMITTED`, and is sent with revision `Any` (a stated exact revision must match). Its reply is cached for exact replay like every reply, so a replay prepares nothing. The session executes it, not the one-call protocol path, which answers `UNAVAILABLE`.

**Request** (`SpectrumConfigureRequest`): `1:form U8 R` (single `1`, collection `2`), `2:entry MESSAGE O*`, `3:maximum-capture-bytes U64 R`, `4:hop-frames U32 O` (`256`, `512`, `1024` or `2048`; absent: the session shape's default cadence). An entry (`SpectrumEntry`) is `1:target-kind U8 R` (track post-input `1`, track post-pan `2`, output `3`), `2:target-id UTF8 R` (1 to 127 bytes) and `3:channels U8 R` (left `1`, right `2`, both `3`). A single form holds exactly one entry; a collection holds zero or more, and an empty collection with budget `0` removes every tap. A code outside its table, an identity outside 1 to 127 bytes, another hop and a single form without exactly one entry are `INVALID_FIELD` on encode and decode. The budget rules are the core's (`INVALID_FIELD`, `spectrum.budget`).

**Reply** (`SpectrumConfigured`): `1:revision U64 R` (the committed revision, unchanged), `2:configured-epoch U64 R`, `3:adopted-epoch U64 R`, `4:rebuild BOOL R`, `5:plan-epoch U64 O`, present exactly when `rebuild` is true. The configuration is in effect when a later spectrum reply's `adopted-epoch` equals this `configured-epoch`.

`SPECTRUM_CAPTURE` (`0011`, #1595; decision 17, C13) arms, reads, cancels or selects the one-shot window of the session's taps; a ready read carries the window analyzed into 1,025 dB bins. Like `0010` it is monitor state, sent with revision `Any`, executed by the session and cached for exact replay; a replay returns the same bytes and pops nothing.

**Request** (`SpectrumCaptureRequest`): `1:op U8 R` (arm `1`, read `2`, cancel `3`, select `4`), `2:channels U8 O` (read and select only; left `1`, right `2`, both `3`), `3:target-kind U8 O` and `4:target-id UTF8 O` (select only; `0010`'s codes, 1 to 127 bytes), `5:include-window BOOL O` (read only; absent is false). A field outside its operation, or a missing one, is `INVALID_FIELD`.

**Reply** (`SpectrumCaptureReply`): `1:adopted-epoch U64 R`, `2:selection-epoch U64 R` (zero on a single configuration), `3:status U8 R` (done `1`: an arm, cancel or select succeeded; pending `2`: no complete window yet; ready `3`). A ready reply adds, and no other reply carries: `4:target-kind U8`, `5:target-id UTF8`, `6:channels U8`, `7:sample-rate-hz U32`, `8:window-frames U32` (2,048), `9:bin-count U32` (1,025), `10:floor-db F32` (-120), `11:captured-sample U64`, `12:end-sample U64` (`captured-sample + 2048`), `13:snapshot-token U64` (from 1), `14:source-underrun BOOL`, `15:frequencies-hz PACKED_F32` (1,025 words), `16:left-db` and `17:right-db PACKED_F32` (1,025 words each, present exactly when `channels` holds that plane), `18:left-window` and `19:right-window PACKED_F32` (2,048 words each, present exactly when the read asked for the window and `channels` holds that plane). A reply that breaks a rule is `INVALID_FIELD` on encode and on decode.

`SPECTRUM_STREAM` (`0012`, #1595; decision 17, C13) starts, selects, reads, resets or stops the continuous spectrum of the session's taps; a ready read carries the window analyzed with the stream's smoothing. Like `0011` it is monitor state, sent with revision `Any`, executed by the session and cached for exact replay.

**Request** (`SpectrumStreamRequest`): `1:op U8 R` (start `1`, select `2`, read `3`, reset `4`, stop `5`), `2:smoothing-ms F64 O` (required on start; optional on select, absent keeps the smoothing; finite, 0 to 10,000), `3:target-kind U8 O`, `4:target-id UTF8 O` and `5:channels U8 O` (select only, all three; `0010`'s codes). A field outside its operation, or a missing one, is `INVALID_FIELD`.

**Reply** (`SpectrumStreamReply`), the stream's metadata after the operation: `1:adopted-epoch U64 R`, `2:selection-epoch U64 R`, `3:status U8 R` (inactive `0`, warming `1`, pending `2`, gap `3`, failed `4`, stopped `5`, ready `6`; none is a refusal), `4:target-kind U8 R` and `6:channels U8 R` (both `0` without a selection), `5:target-id UTF8 O` (present exactly with a selection), `7:sample-rate-hz U32 R`, `8:quantum-frames U32 R`, `9:hop-frames U32 R`, `10:capture-epoch`, `11:sequence`, `12:dropped-captures` (the windows the bounded queue dropped in the capture epoch), `13:windows`, `14:captured-sample`, `15:end-sample`, `16:analysis-epoch`, `17:history-start-sample` (all `U64 R`), `18:smoothing-ms F64 R`, `19:source-underrun BOOL R`. A ready reply adds, and no other reply carries: `20:frequencies-hz`, `21:left-db` and `22:right-db PACKED_F32` (1,025 words each, a plane present exactly when `channels` holds it); a ready reply has a selection, `end-sample = captured-sample + 2048` and `windows = sequence + 1`. Only a read answers `ready`. A reply that breaks a rule is `INVALID_FIELD` on encode and on decode.

`LOUDNESS` (`0014`, #2115) starts, reads, resets or stops the session's output loudness meter: ITU-R BS.1770-5 momentary, short-term and integrated loudness, EBU Tech 3342 loudness range and BS.1770-5 Annex-2 true peak of the rendered master pair. Like `0012` it is monitor state, sent with revision `Any`, executed by the session (the one-call path answers `UNAVAILABLE`), emits no `SESSION_COMMITTED` and is cached for exact replay.

**Request** (`LoudnessRequest`): `1:op U8 R` (start `1`, read `2`, reset `3`, stop `4`). Another op is `INVALID_FIELD` on encode and decode.

**Reply** (`LoudnessReply`), one form for every op, the meter's state after it: `1:observed-sample U64 R` (the end of the last delivered hop of this arming; before the arming's first hop the sample it was armed from; 0 before any start), `2:armed BOOL R`, `3:integrating-since U64 O` (the first sample integration counts from, present once a kept hop arrived), `4:hops-dropped U64 R` (hops render dropped because the record queue was full, monotone over the session's life), `5:sanitized-samples U64 R` (non-finite master samples read as zero in kept hops since reset), `6:gated-block-count U64 R` (gating blocks above both BS.1770 gates since reset), and the levels, each absent until defined: `7:momentary-lufs`, `8:short-term-lufs`, `9:integrated-lufs`, `10:loudness-range-lu`, `11:momentary-max-lufs`, `12:short-term-max-lufs`, `13:true-peak-left-dbtp` and `14:true-peak-right-dbtp` (since reset, present together and exactly with `integrating-since`), `15:hop-true-peak-left-dbtp` and `16:hop-true-peak-right-dbtp` (the last delivered hop, present together), all `F32 O`. Every level is finite and at or above -120 (silence and a zero true peak read -120); a loudness range is finite and at least 0. A reply that breaks a rule is `INVALID_FIELD` on encode and on decode.

## Events

Reliable `8001` contains sequence, origin request ID, previous revision, and operation count. Reliable `8010` contains sequence `1:U64 R`, state `2:U8 R`, effective sample `4:U64 R`, and optional origin request ID `5:U64 O`; field `3`, the position, is **retired** (#1635). Reliable `8011` (`OBSERVATION_ENDED`, #1584) is the one event of a commit that ended host-local observation subscriptions, and it carries every ended key of that commit. It contains sequence `1:U64 R` and one repeated key message `2:MESSAGE R` per ended tap, at least one. A key message holds strip ID `1:UTF8 R`, section `2:U8 R` (inserts `2` or console `5`, the rack codes), the insert's effect ID or the console slot ID `3:UTF8 R`, and the effect-local tap ID `4:U32 R`. The keys are in strictly ascending order: the strip ID, then console slots before inserts, then the effect ID, then the tap ID; so a key never repeats. The event header's revision is the revision that ended the taps. Both IDs are stable IDs, and any other section code, an empty key list or a key out of order is `INVALID_FIELD`. It is advertised with `8001`, in the session family, when the endpoint keeps observation subscriptions. Lossy `8020` (#1583 D2) reports one closed meter window: observed sample `1:U64 R`, the window's exclusive end; record count `2:U16 R`, record bytes `3:U16 R` and the fixed 16-byte meter array `4:BYTES R`; the window's first sample `5:U64 R`, below field `1`; and the window sequence `6:U64 R`, from `1` after each accepted configuration. An empty window or a zero sequence is `INVALID_FIELD`. A record's handle is the 1-based index of its meter table entry. Lossy `8021` contains observed sample plus ascending counter values. Reliable `8030` contains one diagnostic with provider sequence. Reliable `8040` (`RESPONSE_READY`, #1578 D2) is the result of one strip `000e` request: `1:sequence U64 R`, `2:request-tag U64 R` (the tag the request's reply carried), `3:strip-id UTF8 R` (a stable ID), `4:outcome U16 R` (a status: `OK` `0`, or a refusal `NOT_FOUND` `13`, `UNAVAILABLE` `14`, `LIMIT_EXCEEDED` `6` or `INTERNAL` `18`), `5:diagnostic UTF8 O` (the refusal's code, 1 to 127 bytes, present exactly when the outcome is not `OK`), then the capture, present exactly when the outcome is `OK`: `6:captured-sample U64`, `7:sample-rate-hz U32`, `8:floor-db F32`, `9:frequencies-hz PACKED_F32` (at least 2 points) and `12:excluded-count U32`, with at least one of `10:left-db` and `11:right-db PACKED_F32` of the length of field 9, all finite, and `13:member MESSAGE O*`, one per owner in signal order. A member (`ResponseMember`) is `1:section U8 R` (builtins `4`, console `5`, inserts `2`), `2:slot-id UTF8 O` (a stable ID, present exactly for console and inserts), `3:effect UTF8 R` (the native ID, 1 to 127 bytes), `4:kind U8 R` (parametric EQ `1`, input filters `2`, unavailable `3`), `5:bypassed BOOL R`, `6:enabled-left U32 R`, `7:enabled-right U32 R` and `8:section-count U8 R` (at most 32, the number of valid mask bits; neither mask sets a bit at or above it). The codec refuses every other shape, on encode and on decode. `protocol::response_ready_encoded_bound(points, channels, owners)` is the largest frame of the event, with every identity and the diagnostic at 127 bytes. Events have header request ID zero; reliable events have endpoint-monotonic payload sequence.

A stored automation segment applies on `[start,end)` and holds its end value until replaced; the session schema states this hold rule (`SESSION_SCHEMA_V1.md`, #1626).

Strip addressing (#1204). The strip opcodes (`0204`–`0209`, `020c`, `0211`, and the retired `0203`, `020a`, `020b`, `020d`–`0210`) address a **strip ID**, and nothing else about them changed: no opcode, field, code or wire position moved, and the field once named "track ID" is the same first field with the same type.

- **D1.** A track ID names the track's strip and a submix ID the submix's. The Rust variant and field names (`SetTrackRack { track_id, .. }`) are unchanged internal names; each field's doc says it names a strip.
- **D2.** `0202` (source assignment) stays track-only: a submix ID is `session.edit.not_found`. An output ID is `session.edit.not_found` for every strip opcode in the base model, with two exceptions by design: a structural or declaration edit with rack `console` answers `session.edit.console_slot_fixed` first (D3), and a submix upserted under an output's ID earlier in the same transaction is resolved by a strip edit, after which final validation refuses the whole transaction with a duplicate ID rather than `not_found`.
- **D3.** Rack and knob semantics are unchanged; only the resolution widens. The structural and declaration edits refuse a submix's `console` rack as `session.edit.console_slot_fixed` before any lookup, exactly as for a track (so an unknown ID with rack `console` still answers `console_slot_fixed`); a `SET_CONTROL` at a console section edits the submix's entry for the slot; rack `builtins` stays `session.edit.not_found`; and the slot-set rule below (#1202) stands.
- **D4.** A strip ID resolves **tracks first, then submixes**. A validated model has one match at most, because IDs are unique across tracks, submixes and outputs; inside a transaction, before final validation, a track and a submix may briefly share an ID (`0300` is a plain upsert), and then the track wins.
- **VCAs (#1241).** A strip opcode never resolves a VCA ID: `0204`–`0211` at a VCA ID are `session.edit.not_found`, and a `SET_CONTROL` at a strip address with a VCA ID is `control.address.unknown`. A VCA's fader changes only through its `SET_CONTROL` rows or `0700`.

Control smoothing (#1365, decision 15 D15-1, D15-3; `0008` retired by #1561, decision 17 D4a). The session's `control_smoothing` (#1054) is written by `SET_CONTROL` of the three session rows `fader_ms`, `mute_ms` and `pan_ms`; canonical JSON reads `{ "kind": "explicit", "mute_ms", "fader_ms", "pan_ms" }` after the first write, which takes the two lengths it did not name from the default table. No transaction writes the `{ "kind": "default" }` arm back: only a document replace can. Rendered behaviour is the same, because `SET_CONTROL` of the three rows to the default table's values stores an explicit arm whose lengths round to the default arm's sample counts. No prepared plan reads the key, so the edit commits without a plan rebuild: the next live record any later edit produces uses the new lengths, and a ramp already in flight keeps the length it started with.

Retired value ops (#1561, decision 17, C5). `SET_CONTROL` is the one way to set a value. The thirteen per-kind value ops `0008`, `0203`, `020a`, `020b`, `020d`, `020e`, `020f`, `0210`, `0504`, `0505`, `0506`, `0507` and `0702` are retired: each is refused at decode as every unallocated code is (`MALFORMED_FRAME`, whatever the payload holds), and none is ever reallocated. `0211` stays allocated for its structural use only: a transaction that carries it with no `0007` before it that changes the console is refused whole at that edit with `VALIDATION_FAILED` and `session.edit.value_op_retired`, and nothing commits; a console knob's value is a `SET_CONTROL`.

Set control (#1553, decision 17, C5). `0800` sets any control of the control list by its stable address, with the address message above (`control` and `lane` required; the owner ID, slot ID and codes follow the list's rules, and an address that breaks them is `INVALID_FIELD`). The value is any `F32`; a non-finite value is decoded and refused by the validator, so the refusal names the edit. The core's one validator runs inside the edit, before the model changes and before the compile: a refused edit refuses the whole transaction with `VALIDATION_FAILED` and a diagnostic at `edits[i]` whose code is the control code itself: `control.address.unknown`, `control.read_only`, `control.inactive`, `control.lane`, `control.domain`, `control.ramp.fixed`, `control.ramp.conflict`, `control.effect.changed` or `control.monitor` (the monitor rows, `solo` and `master` (#1683), are held by the host and have no session writer: the refusal belongs to the one-call path only, `controls::set` on a monitor row; the prepared path takes a write of either as a monitor write and replies edit path `4`, monitor). Whether the committed edit is live or a rebuild is the classifier's answer for the resulting model, exactly as for any other edit that writes the same field.

Expected effect (#1678). The address message of `0800` has one more optional field than the list's, `7:expected-effect UTF8 O`: the stable ID of the native effect the edit was written for. It is allowed only when the section is `inserts` or `console` (any other section is `INVALID_FIELD`, never ignored) and must be a stable ID. The row's numeric `control` depends on the effect the insert or console slot runs, and a rebuild can replace that effect, so an edit that names an expected effect is checked, inside the edit and before any write, against the effect the candidate model runs at that slot or insert: a different native effect, or a `cid` one, refuses the whole transaction with `VALIDATION_FAILED` and `control.effect.changed` at `edits[i]`. An address that names no insert or slot is still `control.address.unknown`. An edit that names no expected effect applies to whatever runs there, as before. The list's own address message and a stored automation target have no seventh field. The check is the core's, so the browser host and the C ABI refuse alike.

Per-edit ramp length (#1394, decision 15 D15-1, D15-3). Each live-value edit (`0007`, `0211` and `0800`) appends one optional field, `ramp_samples` (`U32`), after its last field: an in-place V1 field, with no new opcode and no ABI feature bit. Absent means the session's `control_smoothing`, and an explicit `0` is legal and steps that edit only; the decoder keeps the two apart. A value above the committed `sample_rate_hz` (one second) refuses the whole transaction before anything commits with `VALIDATION_FAILED` and diagnostic `session.edit.ramp_out_of_range` at `edits[i]`, the offending edit's index; the bound uses the rate the transaction commits. The length is transaction metadata: never model state, never in canonical JSON, and the next edit without one uses the session default.

| Opcode | Variant | `ramp_samples` field | Rows it names |
| ---: | --- | ---: | --- |
| `0007` | set console | `2` | console link |
| `0211` | set strip console | `3` (after the repeated entries) | link |
| `0800` | set control | `3` | the one row the address names, if it ramps (below) |

The last `0007` or `0211` of a transaction that writes a link row decides its length (`Some(n)` sets it, absent removes it), and these clear every length of their target: the four upserts `0200`, `0300`, `0500` and `0700` and the four removals (#1394 D3; a rack edit writes no ramp row and clears nothing, #1561). The effect-bypass crossfade (#1341) and effect parameters have no per-edit length. `0800` names one row by its address: the row's descriptor ramp row decides it (builtin fader and mute, `pan` and the matrix rows with the own `matrix_mode` row, trim and polarity as input, a route's gain, mute and follows-mute and matrix rows, a VCA's offset and mute), and every other row has a fixed ramp, which refuses an explicit length as `control.ramp.fixed`. Several `0800` rows share one ramp row (the fader's two lanes, `pan` and the matrix rows, trim and polarity, a route's mute and follows-mute), and the row holds one length: when one transaction gives two such edits two different lengths (an explicit one against another, or against none, which means the session default), the later edit is refused as `control.ramp.conflict` at `edits[i]` before any write. Equal lengths agree. An upsert of the target between them clears the row.

Arm tags (#1585 D5). A `0003` or `0013` success response carries field `3`, observe arm tags, exactly when the transaction holds `Observe` edits: one tag per `Observe` edit, in transaction order. It carries field `4`, removed arm tags, exactly when the commit ended subscriptions: the tags of the ended bindings, in key order, the keys the commit's `8011` event carries. A present field holds at least one tag; a decoder refuses an empty one. A tag is a nonzero `u64` the host issues per queued observation record, monotone per session; its meaning is in [`CONTROL_PROTOCOL_SEMANTICS.md`](CONTROL_PROTOCOL_SEMANTICS.md) ("Observation subscriptions").

Observe (#1584, decision 17, C9). `0801` arms (`armed` 1) or disarms (`armed` 0) one observation tap of an effect, addressed by its strip, its console slot or insert and its effect-local tap ID. Any other address shape (a `control` or `lane` field, a route, VCA or session owner, a `builtins` or `own` section, a missing ID) is `INVALID_FIELD` at decode. A disarm carries field `5`, the tag the disarmed arm's reply gave (#2087); an arm with field `5` or a disarm without it is `INVALID_FIELD` on encode and decode. The field's value is the core's to judge, `0` included. Adding it moved no frame layout, capability flag or `ABI_VERSION`. The edit carries no ramp and writes nothing to the model; its semantics, refusal codes and sharing rule are in [`CONTROL_PROTOCOL_SEMANTICS.md`](CONTROL_PROTOCOL_SEMANTICS.md) ("Observation subscriptions").

There are exactly 36 allocated opcodes (#1553 opened the control family with `0800` and #1584 appended `0801`, and #1561 retired thirteen value ops: `0008`, `0203`, `020a`, `020b`, `020d`–`0210`, `0504`–`0507` and `0702`). Issue #241 retired three: `0006` (set limits), `0102` (set source sample rate) and `0104` (set source mapping), whose subjects left the schema with the `limits` table and the nested source mapping/region. Retired codes are **never reallocated** -- a v1 peer that spells one must be refused, not reinterpreted, which is why `SessionEditOpcode::from_raw` returns `None` for them and a conformance row pins that. A successful atomic transaction replaces the typed `SessionModel`, immutable control-plane `CompiledSession`, and revision together; its canonical snapshot is the committed canonical JSON, never a compiled/render-plan serialization.

The nested model registry is: render/output profile `1:id,2:mode/channels,3:sample-format`; source `1:id,2:content,3:channels,4:bit-depth,5:frames`; console `1*:pre-insert slot,2*:post-insert slot`; console slot `1:slot,2:identity,3:quality,4:link-mode` (no sidechain field); track `1:id,2:source,3/4:channels,5:builtins,7:inserts,9:fader,10:matrix/pan,11*:console entry`; submix `1:id,2:builtins,3*:console entry,4:inserts,5:fader,6:matrix/pan` (field 6 is tagged exactly as the track's field 10, #1199; field 3 repeats the track's field-11 console entry, #1202); console entry `1:slot,2:bypass,3*:parameter,4:link-mode` (field 4 is required and appended by #1369: `slot` 1, `dual_mono` 2, `maximum` 3, `average` 4); effect `1:id,2:identity,3:quality,4:bypass,5:link-mode,6*:parameter,7:sidechain`; route `1:id,2:source,3:destination,4:matrix,5:gain,6:mute,7:follows-mute` (fields 6 and 7 are required booleans, #1216 and #1218; field 7 may be `true` only on a route into a submix, and `true` on a route into the output is refused at validation, not by the codec); automation `1:id,2:target,3*:segment`; VCA `1:id,2:fader,3*:member` (#1241; a member is a stable-ID string, an empty member list is zero occurrences of field 3, and the session model's root field for `vcas` is `16`, #1240). Route source (also a routed sidechain's source and the `SetRouteSource` value) `1:kind,2:id,3:tap`: kind `1` (track) and kind `2` (submix) both require field 3 (#1203; a tag-2 source without it is refused, and the retired JSON spelling `submix_output` is the same tag 2, now spelled `submix` with a required tap). A route source's tap codes, on a track or a submix, are input `1`, post_input `2`, insert_send `3`, insert_return `4`, pre_fader `5`, post_fader `6`, post_pan `7`. Tagged nested values use field `1:kind`; unknown enum/tag values reject and allocated codes never renumber within v1. The render-profile mode enum has one live code, `1` (`single_thread`); issue #1063 retired `2` (`dependency_waves`), which now refuses like any unallocated code and is never reallocated.

### Decision 12: the session console (#1093, #1094)

Owner decision 12 (`docs/rulings/engine-footprint-2026-09-29.md`, "Wire identity") is an in-place v1 amendment on the #1063 precedent: nothing is renumbered, every retired code is refused and never reallocated, appended codes take the next unallocated ID, and there is no protocol major or minor increment and no `ABI_VERSION` bump. The prelaunch identity stays v1.

- **Renamed in place.** The track taps keep codes `1`–`7` under the spellings above (they were `input`, `post_input_builtins`, `post_simd1`, `post_dynamic`, `post_simd2_pre_fader`, `post_fader`, `post_matrix`). Rack code `2` is `inserts` (was `dynamic`), with the same semantics, and track field `7` carries it.
- **Retired.** Rack codes `1` (`simd1`) and `3` (`simd2`) refuse at decode in every rack-addressed edit and automation target (`MALFORMED_FRAME`). Track fields `6` (`simd1`) and `8` (`simd2`) refuse in either flag form: a mandatory one is `UNKNOWN_REQUIRED_FIELD`, and an optional one is `MALFORMED_FRAME`, never skipped as an unknown optional field would be.
- **Appended.** Rack code `5` (`console`); track field `11` (console entries) and the console, console-slot and console-entry messages; opcodes `0007` (set console) and `0211` (set track console). The session model's own root field for the console is `15`.

Console addressing. A console slot's `slot` ID is session-level and unique across both sections; every strip, track or submix (#1202), carries one entry per slot, in slot order.

- `0007` replaces the whole declaration: both sections and each slot's identity, quality and link mode. It is the only edit that changes the slot set.
- `0211` gives one strip its whole entry array (a track's or, #1204, a submix's) after a `0007` of the same transaction (#1561). It cannot change the slot set: an entry array that adds, drops or reorders a slot refuses at final validation.
- A `SET_CONTROL` at a console section (the slot ID in the address) edits one strip's entry, a track's or a submix's (#1204); a slot the strip does not carry is `control.address.unknown`. (`020a`, `020d` and `020e` did this until #1561 retired them.)
- `0204`–`0209` and `020c` (set rack, put, remove, order, identity, quality, sidechain) with rack `console` are refused as `VALIDATION_FAILED` with diagnostic `session.edit.console_slot_fixed`, whatever the model holds. A strip, track or submix, cannot add, remove or reorder a slot, a slot's declaration is the session's, and a slot has no sidechain. With rack `builtins`, every rack-addressed edit is `session.edit.not_found` (#178).

A transaction that changes the slot set (adds, removes, renames or reorders a slot) must rewrite every strip's entries in the same transaction: every track's with `0211` or `0200`, and every submix's with `0300` (#1202) or, since #1204, `0211`. The store validates only the final candidate, so the rewrite may follow the declaration in any order; a transaction that skips a strip fails final validation with that strip's `console.entry_missing`, `console.entry_order` or `reference.missing_entity` (at `$.tracks[<i>].console` or `$.submixes[<i>].console`), and is refused whole. Nothing is committed and nothing is acknowledged: the refusal is decided before the response is written, as for every transaction. A declaration change that keeps the slot sequence (a quality, link mode or identity change, or moving a slot across the section boundary without reordering it) leaves every entry valid and needs no rewrite; effect preparation judges the parameters against a changed identity, as it does for `0208` on an insert.
