# MISO control protocol semantics

This defines controller behavior for the [BTLV bytes](CONTROL_BTLV_V1.md) and [registry](CONTROL_PROTOCOL_REGISTRY.md). It does not publish a plan, execute a seek, define DSP parameter meanings, or transport PCM.

## Revision, transaction, and replay

The committed `SessionModel` owns its revision, and the revision lies in `0..=9223372036854775807` (2^63 - 1, the session schema's domain; the wire field stays `u64`); command `revision-any` is therefore the header flag plus a zero carrier, never a revision sentinel. Structural edits require an exact revision and at least one edit; a configured zero edit limit disables the transaction command and its paired session events in capabilities and dispatch. Transactions clone/apply/compile a candidate typed session and replace `(SessionModel, CompiledSession, SessionRevision)` only when all validation, capacity reservation, and compilation steps succeed. One success increments once; malformed input, empty input, validation/compile/resource failure, backpressure, and replay leave model and revision untouched. A mutation at revision 2^63 - 1 returns `REVISION_EXHAUSTED` before the candidate is built; the controller does not turn a compiled session into a `PreparedRenderPlan`.

All v1 operations are absolute and idempotent. A new logical command has a nonzero, strictly increasing endpoint-local request ID. The bounded replay cache stores exact canonical request and response bytes. Identical repeated bytes return the cached response without execution; same ID with changed bytes returns `REQUEST_ID_REUSE`; evicted/retired IDs return `REPLAY_EXPIRED`. Completed backpressure is replayed too, so retrying it uses a new ID. Cache capacity is reserved before execution; an unretainable response is rejected before state changes. The guarantee ends with the endpoint lifetime; reconnect recovery belongs to an adapter.

## The response preview (decision 17, C13, #1573)

`RESPONSE_GET` is a read of the committed model: it writes no session, revision, catalog or cell, and an exact replay returns the cached bytes without preparing an owner. On a session endpoint the sample rate and the render quantum are the committed session's, never the request's (`response.rate.session`), so the same request gives the same curves the browser gives at that rate. The provider sizes the reply from its shape (`response_result_encoded_len`) after the owner is prepared and before any curve is computed, and refuses a reply that would exceed the smaller of the endpoint's frame limit, the replay cache's response bound and the request's `maximum-reply-bytes`; the controller checks the reply it is given against the response bound again, so no provider can cache an oversized reply. Every refusal is a typed status with one error diagnostic that carries its code, and changes nothing.

## Automation and events

There is one way to make a change at a sample time: a stored automation edit (`SessionEdit` opcodes `0600`-`0603`), which the engine renders from the session's stored automation table (#1058). The command `AUTOMATION_ENQUEUE` (`0006`), which once admitted a batch of timed records to a queue, is **retired** (#1627, under the owner ruling in `rulings/engine-footprint-2026-09-28.md`: sample-timed delivery had no product consumer, and a host that admitted a batch acked work that no PCM reached). A frame under message ID `0006` is refused at decode as `UNSUPPORTED_MESSAGE`, before the revision check, so no revision, event, queue or replay entry changes and no ack can precede a drop; no endpoint lists `0006`, flag bit 5 or the capability fields that described its admission (9, 12, 19 and 20), and statuses 15 (`TIME_IN_PAST`) and 16 (`AUTOMATION_ORDER`) are retired with it. Every retired code is refused, never reallocated and never renumbered (see the [registry](CONTROL_PROTOCOL_REGISTRY.md)). Sample-accurate application of point, step, linear and exponential records is the protocol capability named in `EFFECT_CONTRACT_V1.md` ("V1 runtime automation is `Point` spans …").

**Delivery history (v1).** The delivery of the command was planned by #140, descoped by the owner ruling in `rulings/engine-footprint-2026-09-28.md`, and its unwired partial implementation (the #460 delivery service, its controller facade and the host-core builtin-batch and scalar-point endpoints) was deleted by #1056. #1315 then refused the command `UNAVAILABLE` on both hosts behind a provider feature switch that nothing set; #1627 retired the command and removed the switch. Two outcomes have their own owners instead. Rendering the session's stored automation table is #1058. Live value edits on the C ABI are delivered by #1053: a committed `SESSION_TRANSACTION_APPLY` whose delta is only live values is lowered onto the running plan's live-control lanes, with the same response and events as before. The live values are a track's fader, mute and pan or matrix values (#1257); a changed value of a track effect parameter whose `automation_rate` is `Block`, on a console-slot entry or an insert (#1264), the parametric EQ's live parameters included, which ride prepared targets (#1265); and a track effect's bypass, except the delay's and the multiband compressor's, which rebuild (#1266). A transaction that changes only the session ID, a profile's id or the stored automation table commits with no replacement and no live value (#1260). Every other transaction still replaces the plan, including every submix strip value (#1053 G1), any edit while a VCA is declared (G3) and a mute change on a track that a `follows_mute` route reads (G2) (`C_ABI_V1_QUALIFICATION.md`, "Value-only track edits on the running plan" and the sections after it).

**Sources across a structural transaction.** A committed transaction that replaces the plan does not reset the sources it leaves unchanged. On the C ABI (#1273) such a source keeps its ring, generation and read position across the plan swap; source submissions and seeks address the newest committed session from the commit on, so a host keeps feeding the source contiguously and must not reseek it. PCM is never part of the protocol, so the transaction acknowledges no PCM: PCM already accepted for a source the transaction removed is discarded with its plan, and later submissions for it are refused as `source.id.unknown`. An added source starts at generation 1, frame 0, until the host seeks it; a source whose declaration the transaction changed restarts the same way, in a new ring at generation 1, frame 0, with the PCM accepted for it before the commit discarded with its plan, so the host restarts its feed.

Changing revision or locating transport cancels nothing. The event `AUTOMATION_CANCELED` (`8002`) is **retired** with the command that filled the queue it reported on (#1628; `AUTOMATION_ENQUEUE` is retired, #1627, so no batch is ever accepted and none can be dropped), and a frame under `8002` is refused at decode like any retired ID. A transaction commit reserves only its `SESSION_COMMITTED`; a transport set reserves only its `TRANSPORT_STATE`. `SESSION_COMMITTED`, transport state, and diagnostics are reliable; meter batches and periodic counter snapshots are the only lossy events. A reliable event has a monotonic sequence and queue capacity is reserved before its related commit.

## Queues and telemetry

Control commands, responses, and reliable events reject before related state changes when full and preserve the original item. Telemetry may replace only the latest same `(revision, handle/component)` value, incrementing `telemetry_coalesced`; a new key rejected at capacity increments `telemetry_dropped`. Counters are non-resetting and saturate at `u64::MAX`.

Render-side consumption has a fixed work bound and does no BTLV decode, allocation/free, lock, logging, I/O, syscall, or structural mutation. Queue configuration and formulas are in the [sizing guide](CONTROL_PROTOCOL_SIZING.md). Typed `BACKPRESSURE` identifies queue kind, capacity, pre-attempt occupancy, requested slots, generation, and applicable byte/retry values.

## Snapshots, telemetry, and deferred ownership

Snapshot chunks form canonical UTF-8 only when reassembled; a chunk may split a code point. An any-revision first page returns its observed revision; continuations are exact or conflict. Control and meter handles are scoped to a structure (`structure_epoch`) or a revision and never renderer parameter slots. `CONTROL_LIST_GET` and `CONTROL_STATE_GET` page the control list by cursor and limit; a page read at a structure that is no longer current is `REVISION_CONFLICT` with the diagnostic `control.list.stale`, and the caller restarts from handle `0`. The retired `PARAMETER_METADATA_GET` and `PARAMETER_STATE_GET` (`0004`, `0005`) are refused as `UNSUPPORTED_MESSAGE` and never reallocated. Telemetry configuration is endpoint-local. Providers return typed bounded records, and adapters own transport framing; their boundary is [documented here](CONTROL_PROVIDER_BOUNDARY.md).
