### Root cause and fix

Root cause is as stated (`runtime.rs:2304-2316` arms on per-track SOURCE; a later chain's witness
covers only its own slots). The fix (arm only chains whose every lane's first slot is
`TrackStage::PostInputBuiltins`) is sufficient: tracks are never route destinations
(`session/src/model.rs:438`), a PIB-first chain gathers the Input stage (source + structurally symmetric
input delay), sidechained/opaque slots never bank, partial cohorts pad the builtin bank, PDC lines are
per-edge and channel-symmetric, a resident-input predecessor is never a PIB-first chain. It fails safe if
a PIB stage is ever elided again (#925/#958): the chain disarms.

Standing rows, both armings, 32 blocks, at 8 and 4 lanes (`verify_rows`): all 17 native session rows
identical in bank shape, collapse counters, route folds and digest (`ALL_SAME=true` at both widths).
`chain_shape` 23/23 under both armings (it does not discriminate the fix); `symmetry_witness`,
`track_delay`, `input_liveness_console`, `mono_reengage`, `rt9_resident_bank_input_alloc` pass with it.

### UnitIdentity and resource accounting

The prototype's fifth flag byte fails `cargo check -p graph --target wasm32-unknown-unknown` ("a
UnitIdentity flag no longer fits the row's padding"), as the brief says. Two clean carriers:

* re-encode `banked: bool` as a one-byte three-state kind (plain / bank / bank gathering the track
  input): zero layout delta, no allocation; touches `crates/graph/src/lib.rs:2876`
  (`banked: identity.banked`), which is outside the authorized paths;
* the brief's per-unit `Box<[bool]>` on `Runtime`: measured mutation (field added, mirrors not updated)
  turns `cargo test -p capi --test resource_lifecycle` red (`graph_metadata_bytes` 56403 -> 56435),
  because `runtime_field_bytes`/`observation_runtime_state_bytes` are `size_of::<Runtime>()` minus the
  mirrors `RuntimeWithoutSplitPairTable` / `RuntimeWithoutObservationActivation` (runtime.rs:2205, 2229);
  with the mirrors updated the new table is an uncharged retained allocation, contrary to
  `rt9_identity_metadata_has_no_retained_or_peak_layout_delta`'s claim. Neither capi nor console-workload's
  resource test (`tools/console-workload/src/lib.rs:2382-2408`) is in the gates.

Minor: the count gate "`bank_collapse_counters()[1]` is 1" is width-specific (2 at 4 lanes); the
existing host-core tests avoid width-specific counts. Rack line citations drifted on the batch tip
(`lane_symmetry_bank` 2003 -> 2178; M3 comment 2342-2350 -> 2521-2527). `PlanUnitEligibility` has no
armed bit, so after the fix a later chain can report every lane eligible while it can never collapse.

### Defect in the brief's rule: the joint exact-program key over-demotes

Heterogeneous 16-track session (8 lanes): even ids mono, odd stereo; even ids 8-14 drop simd2. Today the
8 mono tracks share one full simd1 cohort whose `[PIB, EQ, comp]` chain collapses (`collapse [24,1]`).
The brief's groups are 4 + 4, so all 8 are demoted: `collapse [0,0]`, same shape `[4,13]`, nothing
banked in exchange. The global prototype leaves it alone. The gate session is uniform, so it cannot see
this. A rule that follows the planner instead: run `plan_bank_groups` once on the undemoted classes,
demote a mono track only if every effect-rack group it sits in is a partial mono group, then re-plan.
Candidate construction lives in `crates/graph-compiler/src/banks.rs:67-205`, which is not authorized.

Other gaps: `prepared_bank_count` alone cannot catch a demotion applied to one planner only (merges
decline silently, effect bank count unchanged): assert `bank_shape()` too. #969's pin (odd track by
polarity, 21 vs 24 banks) becomes 24 vs 24 with S2 (measured shape `[11,48]` -> `[8,48]`), so bank count
no longer discriminates mutation 959-4; #969 must pin the class map.
