# Mutation pass: per-crate results

Base `a9414c0c`. The runs used `cargo mutants` 27.1.0 through `../tools/run-mutants.sh`, with these
settings:
- opt-level 1 with debug assertions and overflow checks on, which is CI's debug semantics;
- `--no-fail-fast`, so every failing test is recorded for every mutant;
- each crate's own tests only.

Terms:
- A mutant is **caught** when at least one test fails, and a **survivor** when none does.
- **Unviable** means the mutant does not compile.
- A **timeout** counts as detected.
- **Unique** means that test is the mutant's only catcher.
- **Dominated** means one other single test catches every mutant this test catches.

How to read the results:
- The "no catch" and "dominated" lists are *candidates*. A test can guard another crate's code, or a
  property no mutant exercises (allocation, timing, a width-only path), and still score zero here.
  Each issue gate checks this case by case.
- Mutants of fixture generators are reported separately from product code: the compressor's and
  parametric-eq's `src/corpus.rs`, and graph-compiler's `src/bin/graph_fixture.rs`. In all three
  crates, the digest pin's unique catches are almost all mutants of that generator, not of the
  product.
