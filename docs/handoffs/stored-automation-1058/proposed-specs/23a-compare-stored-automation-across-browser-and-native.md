# Compare stored automation bits across the browser and native hosts

Proposed by *Research: render stored session automation in the engine, identically on every
platform* (#1058), answer A5, under decision 15 D15-16
(`docs/rulings/live-updates-seamless-swaps-and-one-control-plane-2026-10-05.md`). A draft for root
to file. Code anchors verified on `6ee64f484`. Batch Q.

## Product outcome

One fixture session automates every row the engine renders, with every shape, and is seeked once
while it plays. The shipped browser artifact (wasm `simd128`) and the native browser host on
x86-64 (AVX2) render it to the same bits, and the C ABI renders the same bits as the browser host.
A second fixture does the same for matrix automation. This is the browser and x86-64 half of the
evidence that stored automation renders identically on every platform; draft 23b adds AArch64 and
seek-time invariance on the same fixtures. It adds no new digest owner: it extends the direct
oracle's existing pins. Batch Q.

## Context

**The existing owners.**
- The G5 corpus is the single owner of the kernels' cross-target digests
  (`tools/wasm-gate-corpus/src/lib.rs:1-20`), run natively by `wasm-gates` and under wasmtime.
  Draft 07 adds the evaluator's event values to it.
- The browser direct oracle renders fixed sessions through the shipped `simd128` artifact
  (`hosts/host-web/tests/browser-v1/direct-oracle.mjs:547-679`). Each leg asserts its PCM digest
  equals a native pin before anything prints (the identity leg, `:571-583`; the command timeline,
  `:584-601`; the observation timeline, `:602-654`).
- Each native pin is written by a host-web test that renders the same session and transcript
  through `AudioWorkletEngineHost` on the host CPU and reads the pin from `expected.json`
  (`native_identity_session_digest_pins_the_wasm_parity`, `hosts/host-web/src/tests.rs:1632`;
  the command and observation twins at `:1751` and `:6690`; the pin reader `serde_pin`,
  `:2255-2300`).
- CI runs the oracle in the `artifact-gates` job through `scripts/check-web-audioworklet.sh` and
  `scripts/check-browser-expected-resources.py --artifacts`
  (`.github/workflows/qualification.yml:331-343`).

**What the oracle drives today.** The command timeline feeds constant PCM and drives live
commands (`direct-oracle.mjs:373-454`). No leg has stored automation or a session seek.

**The C ABI.** No test compares a C ABI render with the browser host's today. #1399 adds the
cross-host harness `hosts/host-web/tests/strip_cells_cross_host.rs`.

## Decisions frozen for this slice

- **D1. Two fixtures**, beside the existing ones in `hosts/host-web/tests/browser-v1/`:
  - `automation-session.json`: two tracks and one submix at 48 kHz, quantum 128. Track 1 automates
    fader, mute, pan, trim, polarity, HPF and LPF on its lanes (one `both` entry and one
    single-lane entry among them), and has a pre-fader route into the submix with
    `follows_mute`. Its inserts carry every span-driven launch effect (compressor, delay with its
    time automated, gate/expander, multiband compressor, soft clip, transient shaper, true-peak
    limiter) and a parametric EQ, each with at least one automated `Block` parameter. Track 2 has
    the same chain with no automation, so a bank holds automated and plain lanes.
  - Across the entries: `step`, `linear` and `exponential` segments (exponential only where a rule
    allows it: draft 02's for the input HPF and LPF, draft 03a's for an effect frequency, time or
    ratio row), a gap, a step on a sample that is not a grid
    sample, and a segment that starts before the seek target.
  - `automation-matrix-session.json`: one matrix strip whose four coefficients are automated.
- **D2. One transcript.** Both fixtures render 96 blocks of PCM generated by an integer formula
  that is exact in `f32` in Rust and in JavaScript, for example
  `x[i] = ((i·40503) mod 65536 − 32768) / 65536`. At block 40 the host makes one session seek to
  timeline 30,000 (draft 06a's export in the oracle, the same control-plane call natively).
- **D3. The browser leg.** `direct-oracle.mjs` gains `runAutomationTimeline` for each fixture. It
  asserts each digest equals `expected.directOracle.nativeAutomationPcmF32leSha256` and
  `nativeAutomationMatrixPcmF32leSha256` before any print, as the existing legs do. The pins are
  written by two new host-web tests beside `:1632`, which `serde_pin` extends to read. Draft 23b
  reuses these two tests and pins.
- **D4. The C ABI equals the browser host.** In #1399's cross-host test, both fixtures and the
  transcript render through the C ABI (draft 05's `miso_engine_v1_session_seek`) and through
  `AudioWorkletEngineHost`, and the two outputs are compared bit for bit in the test. No digest.
- **D5. One-ulp evidence (PR evidence, not committed).** Plant a one-ulp change in draft 07's
  `value_at` result. Record that the two native pin tests, the oracle's `simd128` legs, the
  cross-host test (when the plant reaches only one host's path, as a check of the comparison) and
  the G5 corpus each turn red, then revert.

## Non-goals

- Any engine change. A leg that disagrees is a defect for its own issue, recorded here with its
  first differing sample.
- AArch64 and seek-time invariance (draft 23b).
- A new digest owner, or a digest of a rendered session outside `expected.json`.
- Timing (drafts 24a, 24b). Listening tests.
- Live edits during the fixture: drafts 10a, 10b, 19 and 20 gate them.

## Hazards

- **Pin discipline.** A pin is written only from a native render the `simd128` leg already equals
  (the oracle asserts before it prints). Never mint a pin from one side.
- **The `browser` job.** Its Playwright legs replay `expected.json`; a new key must not break
  `scripts/check-browser-expected-resources.py`'s two-class rule (pins exact, resources
  ceilinged).
- **Hot files.** `hosts/host-web/src/tests.rs` and `expected.json` are stream H's. Root sequences
  the merge.

## Test value

- The automation legs turn red if any row's events, designs or ramps differ between wasm and
  native: a platform transcendental in the evaluator, a fused multiply-add, an FP environment left
  unpinned at preparation (finding F11), or a grid on the render clock.
- The cross-host test turns red if the C ABI and the browser host prepare or seek a session
  differently, which no test compares today.
