## Traversals: the identity does not replace the removed arithmetic pass

Count loop sweeps separately from per-channel sample read/write coverage. For a settled pair of N frames, ignoring unchanged input-stage and outer graph work:

- Old fader executes TWO single-plane gain/mute loops: N left reads/stores and N right reads/stores. Old matrix executes ONE dual-plane loop: 2N reads and 2N stores. Total arithmetic: three loops, 4N scalar sample reads and 4N stores.
- New composite executes ONE dual-plane fader_matrix_block::<f32> loop: 2N reads and 2N stores, preserving exact gain/mute then matrix operands and identity selection. It removes the materialized faded intermediate from the arithmetic pipeline. Total arithmetic: one loop, 2N reads and 2N stores. These are source-level logical accesses, not generated machine instruction/traffic claims.
- The original graph's fader input reduction is unchanged. The matrix's single-input reduction is ALSO unchanged: either zero sample traversal when input buffer equals output, or two plane copies totaling 2N reads and 2N stores when distinct. No additional copy is introduced by changing Bound(matrix) to Identity.
- On a ramping call the composite retains the old three arithmetic loops (or their existing ramp/settled subloops) for the whole call, plus those same reductions. This is correctness fallback, not a settled-fusion claim.

The stable lowering already selects in-place output for a single undelayed sole-reader edge where neither end is dedicated (`program.rs:689–705`). `reduce_plane` checks that exact buffer equality and does nothing in that case (`runtime.rs:90–103`). Thus an eligible ordinary fader/matrix edge can retain TWO runtime op dispatches while its identity op traverses ZERO samples. Require the positive fixture to prove this current in-place case and the actual fused arithmetic dispatch. The claim must not be based merely on one fewer processor object.

If a legitimate selected edge has distinct buffers, the existing copy still traverses samples; that is residual graph placement cost, not an equivalent replacement for the removed arithmetic intermediate. Before: arithmetic4N plus copy2N reads/stores; after: arithmetic2N plus the same copy2N. Removing that residual copy would require an output redirect/liveness/observer proof and is not necessary to deliver the actual arithmetic fusion objective. Do not add it merely to remove the identity dispatch. A copy-free in-place positive demonstrates that this proposed scope is aligned with RT-4 rather than preserving all old memory passes under another name.

The record should say 'one settled scalar arithmetic traversal; original graph reductions retained', not 'one total traversal for every graph', and quote no speedup. Later #431 can measure a workload that actually selects this path. Ordinary control-queue reads/state writes are outside the PCM traversal count and remain mandatory.
