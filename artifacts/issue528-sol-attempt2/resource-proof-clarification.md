Use the existing compressor conformance isolation pattern (`crates/compressor/tests/conformance.rs:90`): the gate-6 test launches its own current test executable with `--exact <that-test-name> --nocapture` and a task-specific `MISO_ENGINE_..._CHILD` marker, then propagates child failure. Only the child performs the measured preparation and real render audit. Process spawning/environment checks occur before any measurement/render audit; they are test-control work. This is a small reuse inside the same test binary, not a new harness. It keeps ordinary parallel suite execution from contaminating process-global preparation totals. Merely mutexing this test does not isolate other tests. A manually isolated invocation may supply evidence, but the self-child pattern is the simplest way to keep the same assertions reliable in ordinary CI too.

Gate6 still requires installed positive allocation/free controls and repeated actual successful Point/read/process/fault-cancellation paths with zero render allocations/frees. No new test family or acceptance requirement is added. This clarification accurately limits the proof method for the existing service-only heap/largest/inline contract and does not approve the implementation itself.
